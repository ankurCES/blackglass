# ADR 0004: Local socket auth = 0600 token file

- Status: Accepted (sub-plan 1)
- Context: spec §2.2 says MCP servers run as operator UID and "talk to core via socket". A world-accessible socket would let any local process impersonate an MCP server (or anything else).
- Decision: The first RPC on every connection MUST be `auth` carrying a 32-byte random token. The core refuses all other methods until `auth` succeeds. The token is read from `~/.local/share/blackglass/operator.token` (mode 0600, owned by the operator UID). The token is (re)generated by `blackglass init`.
- Consequences:
  - Adds 1 RPC method to the surface (manageable).
  - Token rotation = one CLI command, no service restart.
  - Does NOT defend against a process running AS the operator. Out of scope (AppArmor in sub-plan 3 narrows that).
- Alternatives: SO_PEERCRED only (rejected: every operator-uid process is "the operator"), socket directory mode 0700 (rejected: insufficient — anything running as operator can connect), Unix credential SCM message per request (rejected: extra round-trips, no real gain over a single auth handshake).
